# OpenCode 클라이언트 재시작 분석 (2026-10-11 ~ 10-12 로그 기준)

## 결론

- 30분 뒤 "연결이 끊기는" 현상은 **봇의 유휴 종료 정책**입니다. 오류가 아닙니다.
- `bot-config.json`의 `idleShutdownMin: 30`에 따라, 마지막 사용 후 30분이 지나면 풀(`internal/agent/pool`)이 OpenCode 프로세스를 정리합니다. 로그에는 `유휴 종료(30분)`과 `종료 ... err=closed by client`가 함께 찍힙니다.
- 종료된 클라이언트는 **다음 메시지가 올 때** 다시 뜹니다(지연 재기동). 이후 로그에서 `준비 완료` → `resume`이 정상 기록됩니다. 재기동 자체는 실패하지 않았습니다.
- 따라서 "30분 지나도 재시작이 안 된다"는 현상은 재기동이 없는 게 아니라, **메시지가 와야 재기동하도록 설계되어 있어서** 생기는 것으로 보입니다.

## 왜 "재시작이 안 되는 것처럼" 보이나

1. **재기동은 메시지 시점에 일어납니다.** 30분 뒤 프로세스가 없어도 봇은 바로 다시 띄우지 않습니다. 메시지가 오면 `Acquire`가 새 프로세스를 만듭니다. 그래서 채널에 아무 말도 하지 않으면 "꺼져 있는" 상태가 계속됩니다.
2. **재기동 직후 응답이 늦을 수 있습니다.** 프로세스 시작과 `resume`에 수 초가 걸립니다. 로그에서 `준비 완료` 후 `resume`까지 약 0.5~1초, 첫 응답까지는 수십 초가 걸렸습니다. 긴 턴이라면 체감상 "멈춘 것"처럼 보일 수 있습니다.
3. **`closed by client`는 오류가 아니라 봇이 정리했다는 표시입니다.** 원인은 풀의 `Stop()`이고, OpenCode가 연결을 끊은 것이 아닙니다.

## 로그 한계

- 로그 기준으로 재기동 실패는 확인되지 않았습니다. 다만 로그에 찍히지 않은 실패(예: Discord 전송 실패)는 이전 버전에서 디버그 레벨이었습니다. 현재 코드는 경고 레벨로 올려 두었지만, **봇이 아직 재시작되지 않아 이 로그는 아직 기록되지 않습니다.**
- 종료 사유 로그(`[pool] 종료 reason=…`)도 현재 코드에만 있고, 실행 중인 봇에는 아직 반영되지 않았습니다.

## 권장 사항

- 30분 유지가 불편하면 `idleShutdownMin`을 늘리거나 `0`으로 두어 끄기 (메모리 사용 증가).
- 재기동 지연을 줄이려면 봇 시작 시 자주 쓰는 cwd를 미리 띄우는 방법이 있습니다(코드 수정 필요).
- 봇을 재시작한 뒤, 같은 조건(30분 유휴 → 메시지)을 한 번 재현하여 새 로그 줄(`[pool] 종료 reason=idle`, `resume` 결과)이 찍히는지 확인하세요.
